MYARM M750 · RASPBERRY PI 5 · COMPUTER VISION · AI

Autonomous Robot Tic-Tac-Toe

Built an end-to-end system that watches a human play, interprets the board, chooses an optimal response with minimax, and physically places its piece—all locally on a Raspberry Pi 5.

9 board cells taught1-line arm switching100% on-device
Read the engineering case study +

The challenge

The arm’s internal position model was not dependable enough for repeatable physical play. A live reading taken during motion could introduce drift, and unguarded joint commands risked pushing the hardware into its limits.

Control system

I built calibration and teaching scripts that let an operator jog one joint at a time, record stable poses, replay them safely, and enforce live joint limits. Every piece-storage and board position was then taught and validated by hand.

Reliability decision

I rebuilt pick-and-place around stored, verified positions instead of trusting changing sensor readings mid-motion. That practical choice made physical execution repeatable on imperfect research hardware.

Reusable platform

I consolidated six generations of code into one verified project, added multi-arm support through a single configuration change, and extracted the control layer into a documented myArm M750 Operator Kit for future projects.

Camera reads board→Minimax selects move→Stored pose replay→Arm places piece

ROBOTICS · CALIBRATION · VISION · GO · HTMX

Vision-Guided Floor-Painting Arm

Developing an autonomous painting system that finds a taped-off floor tile, infers its correct color from the surrounding checkerboard, paints it with a roller, and performs a quality-control pass.

400 mm roller offset7 mm error per 1°3 pipeline stages
Read the engineering case study +

Perception

I built a pipeline that locates the taped tile and reads the checkerboard around it to decide the target color. It flags uncertainty instead of making a bad paint decision, and I used synthetic images to test the vision logic before the physical setup existed.

Calibration

I mapped camera coordinates into the arm’s working space with hand-probed reference points, avoiding dependence on questionable built-in positioning. The process also measured and confirmed the roller’s true 400 mm offset.

Motion precision

A one-degree wrist error becomes roughly seven millimeters at the roller tip. I hand-teach several points with limp joints, then replay a smoothed path through those exact poses to produce a controlled stripe.

Ownership and interface

When two teammates became unavailable, I carried the calibration, perception, and motion work forward myself. I also built a Go + HTMX dashboard on the Pi with a live camera feed to run and monitor detection, painting, and QA.

PROVEN: perception, calibration, single stripeNEXT: gap-free full-tile coverage + floor-light recalibration

04

MATLAB · MFCC · EUCLIDEAN CLASSIFICATION

Speaker Identification System

Built and evaluated a voice-identification pipeline across four datasets, 20 speakers, and 60 unknown recordings, achieving 95% overall accuracy.

Methods and findings +

Feature pipeline

Extracted 13 MFCCs per frame, stacked three training recordings per speaker, and reduced each database to a representative 13-dimensional mean feature vector.

Classification

Processed three unseen recordings per speaker and used Euclidean distance to choose the closest known voice, recording every comparison and result for analysis.

Results

Correctly classified 57 of 60 tests. Two datasets reached 100%, with the others at 93.3% and 86.7%.

Error analysis

Identified a repeat Daniel/Eliza confusion and traced it to averaging away pitch and temporal information. Proposed pitch features or a more expressive model as the next improvement.

SYSTEMVERILOG · QUARTUS · DE10-LITE FPGA

Finite-State Vending Machine

Designed a complete ten-state vending-machine controller that accepts nickels, dimes, and quarters, dispenses at 25 cents, and returns correct change in hardware.

Design through deployment +

Architecture

Translated system behavior into a state diagram, exhaustive transition table, next-state equations, and output logic for totals from 0 to 45 cents.

Implementation

Used one-hot state encoding and clocked D flip-flop behavior in SystemVerilog, then integrated the module with display and I/O circuitry in Quartus.

Verification

Created a testbench for coin sequences and change scenarios, validated the simulation waveforms, and only then programmed the physical DE10-Lite board.

Hardware result

Switches acted as coin inputs, a pushbutton supplied the clock, LEDs showed dispense/change signals, and seven-segment displays tracked accumulated value correctly.

C++ · DESIGN PATTERNS · NEWTONIAN PHYSICS · JSON

Gravitational System Simulator

Implemented a multi-object orbital simulation that models stars, planets, asteroids, and comets using gravitational forces, time-stepped motion, and a pattern-driven C++ architecture.

4 celestial object types1 sec Earth-orbit timestep3+ design patterns
Architecture and simulation +

Physics engine

Computed pairwise force with the law of universal gravitation, summed net force on every moving body, converted force into acceleration, and advanced velocity and position through discrete time steps.

State consistency

Cloned the universe into a snapshot before each step so every body’s next state is calculated from the same unchanged moment. This prevents earlier updates from contaminating later calculations within a timestep.

Software architecture

Used a Singleton to manage the universe, an Abstract Factory to validate and create celestial bodies, polymorphic object classes, a Visitor for type-specific output, and clone-based Prototype behavior for snapshots.

Data and safeguards

Parsed JSON configurations into the appropriate object types, enforced mass and uniqueness constraints, kept the first object fixed as the central star, and handled zero-distance force safely.

JSON object data→Factory + validation→Force snapshot→New system state

Compile-Time Vector Mathematics Library

Designed a fixed-dimension mathematical vector class from its expected client behavior, supporting natural algebraic syntax without STL containers, dynamic allocation, or explicit loops.

Library design +

Mathematics

Language constraints

API reasoning
