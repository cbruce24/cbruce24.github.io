Autonomous Robot Tic-Tac-Toe

Problem: the arm’s internal position model wasn’t dependable enough for repeatable physical play.

An end-to-end system that watches a human play, interprets the board, chooses an optimal reply with minimax, and physically places its piece, all locally on a Raspberry Pi 5.

Board cells taught
9
Arm switching
1 line
Processing
On-device
  • Raspberry Pi 5
  • myArm M750
  • Computer vision
  • Python
Details

Control system

Built calibration and teaching scripts to jog one joint at a time, record stable poses, replay them safely, and enforce live joint limits. Every storage and board position was taught and validated by hand.

Reliability decision

Rebuilt pick-and-place around stored, verified positions instead of trusting changing sensor readings mid-motion, which made execution repeatable on imperfect research hardware.

Reusable platform

Consolidated six generations of code into one verified project, added multi-arm support through a single configuration change, and extracted the control layer into a documented myArm M750 Operator Kit.

Robotics · SiteVue AI internship · Summer 2026

Vision-Guided Floor-Painting Arm

Problem: a one-degree wrist error becomes roughly seven millimeters at the roller tip.

An autonomous system that finds a taped-off floor tile, infers its correct color from the surrounding checkerboard, paints it with a roller, and checks the result.

Roller offset
400 mm
Error per 1° of wrist
~7 mm
Pipeline stages
3
  • Computer vision
  • Calibration
  • Go
  • HTMX
Details

Perception

Locates the taped tile and reads the surrounding checkerboard to choose the target color, flagging uncertainty instead of making a bad paint decision. Synthetic images tested the logic before the physical setup existed.

Calibration

Mapped camera coordinates into the arm’s workspace with hand-probed reference points, and measured the roller’s true 400 mm offset.

Motion precision

Hand-teaches points with limp joints, then replays a smoothed path through those exact poses to produce a controlled stripe.

Ownership

Carried calibration, perception, and motion forward alone when two teammates became unavailable, and built a Go + HTMX dashboard with a live camera feed to run detection, painting, and QA.

Next: gap-free full-tile coverage and recalibration for floor lighting.

Embedded software · Legacy Audio internship · Spring 2026

Legacy Audio Wavelet Touchscreen

Problem: the Wavelet DSP preamplifier exposed dense functionality through physical controls.

A touchscreen interface for a Raspberry Pi 4 and an 11.9-inch bar display that controls an ADAU1467 SigmaDSP over I²C. Six pages cover inputs and volume, EQ, an 8-channel crossover, room correction, presets, and system settings.

  • Qt 6 / QML
  • C++17
  • Raspberry Pi 4
  • ADAU1467 SigmaDSP
  • I²C
Details

Interface

Home (inputs, volume, mute, standby, level meters), EQ (tone, parametric, graphic, loudness), DSP (per-channel crossover slopes, gain, delay, polarity), Room (correction and speaker distances), Presets, and System.

Back end

A C++ state model exposes 34 controls to the QML screens and writes changes to the DSP through its safeload registers in 5.23 fixed point. A rotary encoder drives volume through Linux evdev.

Product details

Factory presets plus three user slots saved as JSON. The UI starts even when the DSP isn’t connected, so it can be developed off-device. I also wrote a user manual and Raspberry Pi deployment notes.

Outcome

Delivered a working end-to-end prototype and demonstrated it to the engineering team. The source code is private.
